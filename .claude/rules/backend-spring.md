# Spring Boot 서버 규칙

서버 코드를 쓰거나 고칠 때 따른다. 프로젝트에 이미 다른 방식이 자리 잡고 있으면 기존 방식이 우선이고, 그 차이는 프로필의 `리뷰 체크리스트`에 적는다.

## 계층

- 컨트롤러는 요청을 받아 검증하고 서비스를 호출해 응답으로 바꾸는 일만 한다. 비즈니스 로직과 트랜잭션을 두지 않는다.
- 서비스가 유스케이스와 트랜잭션 경계를 가진다.
- 리포지토리·매퍼는 데이터 접근만 한다.
- 계층별 위치는 프로필의 `디렉터리`를 따른다.

## 의존성 주입

- 생성자 주입을 쓴다. 필드 주입(`@Autowired` 필드)을 쓰지 않는다.
- 주입받는 필드는 `final`이다.

## 요청과 응답

- 엔티티를 요청·응답 본문으로 직접 쓰지 않는다. DTO(record 권장)를 둔다.
- 요청 DTO는 Bean Validation으로 검증한다(`@Valid`, `@NotNull`, `@Size` 등). 컨트롤러 매개변수에 `@Valid`를 빠뜨리지 않는다.
- 목록 응답에는 페이징을 둔다. 크기 상한을 둔다.
- 상태 코드를 의미에 맞게 쓴다. 실패를 200으로 돌려주지 않는다.

## 예외

- 예외 응답은 `@RestControllerAdvice` 한 곳에서 만든다. 컨트롤러마다 try-catch로 응답을 만들지 않는다.
- 예외를 삼키지 않는다. 잡았으면 처리하거나, 원인을 붙여 다시 던진다.
- 오류 응답에 스택 트레이스, SQL, 내부 경로를 넣지 않는다.

## 트랜잭션

- `@Transactional`은 서비스의 public 메서드에 둔다. 조회 전용은 `readOnly = true`.
- 같은 클래스 안에서 `@Transactional` 메서드를 직접 호출하면 적용되지 않는다. 그런 구조를 만들지 않는다.
- 트랜잭션 안에서 외부 API 호출, 메일 발송, 파일 업로드를 하지 않는다. 커밋 뒤로 미룬다.
- 체크 예외는 기본적으로 롤백되지 않는다. 롤백이 필요하면 `rollbackFor`를 명시한다.

## 인증·인가

- 새 엔드포인트는 인증이 필요한 것이 기본이다. 공개 엔드포인트는 보안 설정에 명시적으로 연다.
- 자원의 소유자 확인은 서버에서 한다. 요청으로 받은 사용자 식별자를 믿지 않고 인증 정보에서 꺼낸다.

## 설정과 비밀

- 설정 값은 `@ConfigurationProperties`로 묶어 받는다. 코드 곳곳에 `@Value`를 흩어 놓지 않는다.
- 비밀번호·토큰·키를 코드와 `application*.yml`에 적지 않는다. 환경 변수나 비밀 저장소에서 받는다.
- 로그에 비밀 값과 개인정보를 남기지 않는다. 요청 본문 전체를 로그로 찍지 않는다.

## 로그

- SLF4J를 쓴다. `System.out`, `printStackTrace()`를 쓰지 않는다.
- 문자열 결합 대신 자리표시자(`{}`)를 쓴다.
- 예외를 로그로 남길 때는 예외 객체를 마지막 인자로 넘긴다.

## 그 밖에

- 시간은 `java.time`을 쓴다. 현재 시각이 로직에 쓰이면 `Clock`을 주입받아 테스트할 수 있게 한다.
- 돈과 정밀한 수치는 `BigDecimal`을 쓴다.
- `Optional`은 반환값에만 쓴다. 필드와 매개변수에 쓰지 않는다.
- 새 의존성을 추가하기 전에 프로필의 `재사용 우선 대상`과 기존 의존성으로 되는지 본다. 추가했으면 보고에 적는다.
