# 화면 코드 규칙

화면 코드를 쓰거나 고칠 때 따른다. 프레임워크와 디렉터리는 프로필의 `스택`, `디렉터리`를 따른다. 대상 경로가 프로젝트와 다르면 위 `paths`를 고친다.

## 먼저 찾기

- 새 컴포넌트·유틸·API 호출 함수를 만들기 전에 프로필의 `재사용 우선 대상`과 기존 코드에서 같은 것을 찾는다.
- 기존 화면의 작성 방식(상태 관리, API 호출, 폼 처리, 스타일)을 따른다. 새 방식을 들여오지 않는다.

## 보안

- 사용자 입력과 서버에서 받은 문자열을 HTML로 그대로 넣지 않는다(`innerHTML`, `v-html`, `dangerouslySetInnerHTML`, Thymeleaf `th:utext`). 꼭 필요하면 정제하고 이유를 주석으로 남긴다.
- 토큰·키·비밀 값을 화면 코드와 번들에 넣지 않는다.
- 화면에서 숨기는 것은 권한 검사가 아니다. 권한은 서버가 검사한다.
- 상태를 바꾸는 요청은 GET으로 보내지 않는다.

## 상태와 요청

- 요청마다 로딩, 실패, 빈 결과 상태를 화면에 둔다. 실패를 조용히 삼키지 않는다.
- 저장·결제 같은 버튼은 요청 중에 다시 눌리지 않게 한다.
- 화면 검증은 편의다. 같은 검증이 서버에도 있어야 한다.
- 서버 오류 메시지를 사용자에게 그대로 보여 주지 않는다.

## 접근성과 테스트 가능성

- 클릭하는 것은 `button`이나 `a`로 만든다. `div`에 클릭 핸들러를 달지 않는다.
- 입력에는 `label`을 연결한다. 이미지에는 `alt`를 둔다.
- E2E가 역할·라벨·텍스트로 요소를 찾을 수 있어야 한다. 그렇게 찾기 어려운 요소에만 `data-testid`를 붙인다.

## 그 밖에

- 날짜·금액·숫자 형식은 한 곳의 포맷 함수로 맞춘다.
- 사용자에게 보이는 문구는 기존 화면의 용어와 맞춘다.
- 쓰지 않게 된 컴포넌트·스타일·import는 같은 커밋에서 지운다.
