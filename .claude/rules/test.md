# 테스트 규칙

테스트를 쓰거나 고칠 때 따른다. 실행 명령은 프로필의 `명령`을 따른다. 대상 경로가 프로젝트와 다르면 위 `paths`를 고친다.

## 공통

- 작업 하나를 구현할 때 그 작업의 테스트를 같은 커밋에 넣는다.
- 테스트는 동작을 검증한다. 구현 세부(내부 메서드 호출 횟수, private 상태)에 묶지 않는다.
- 테스트 이름은 조건과 기대 결과를 말한다. 예: `취소된_주문은_다시_취소할_수_없다`
- 테스트는 서로 독립이다. 실행 순서, 다른 테스트가 남긴 데이터, 현재 시각, 외부 네트워크에 기대지 않는다.
- 정상 경로 하나로 끝내지 않는다. 계획 문서의 수용 기준과 결정 사항에 나온 예외·경계 상황을 테스트한다.
- 테스트 코드에 실제 비밀번호·토큰·개인정보를 넣지 않는다.

## 실패를 감추지 않는다

- 통과시키려고 단언을 지우거나 약하게 만들지 않는다.
- `@Disabled`, `test.skip`, `test.fixme`로 실패하는 테스트를 꺼 두지 않는다. 꼭 필요하면 이유를 적고 보고에 올린다.
- 기존 테스트가 깨지면 먼저 코드가 틀렸는지 본다. 테스트의 기대값을 바꾸는 것은 동작 변경이 계획 문서에 있을 때만 한다.
- 가끔 실패하는 테스트를 재시도로 덮지 않는다. 원인을 찾는다.

## 서버 테스트 (Spring Boot)

- 가장 좁은 범위로 쓴다. 로직은 순수 단위 테스트, 웹 계층은 `@WebMvcTest`, 데이터 접근은 `@DataJpaTest`나 그에 해당하는 슬라이스. `@SpringBootTest`는 여러 계층이 함께 돌아야 확인되는 것에만 쓴다.
- 데이터 접근 테스트는 실제 DBMS와 같은 종류로 돌린다. 운영이 MariaDB·PostgreSQL인데 H2로만 검증하지 않는다(가능하면 Testcontainers).
- 목(mock)은 외부 경계(외부 API, 메일, 시계)에 쓴다. 검증하려는 대상 자체를 목으로 만들지 않는다.
- 인가가 걸린 엔드포인트는 권한이 없는 경우도 테스트한다.

## E2E (Playwright)

- 수용 기준 하나에 테스트가 하나 이상 있고, 테스트 이름은 `AC-<n>:`으로 시작한다.
- 요소는 역할·라벨·텍스트로 찾는다. 안 되면 `data-testid`. CSS 클래스와 DOM 구조에 기대지 않는다.
- `waitForTimeout`을 쓰지 않는다. 자동 대기와 `expect`의 재시도에 맡긴다.
- 기준 URL과 계정은 환경 변수와 프로필의 `E2E`에서 가져온다.
- 작성과 실행은 `/verify`가 `tester` 에이전트로 한다.
